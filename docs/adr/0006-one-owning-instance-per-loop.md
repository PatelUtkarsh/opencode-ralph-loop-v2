# One plugin instance owns each Loop, identified by its directory

OpenCode loads one plugin instance per loaded location, so a user with the plugin in their global config and two projects open runs two or three `ralph-loop` instances at once. They share `ctx.storage` (scoped by plugin id) and each receives the whole event stream, and the `session.execution.*` events carry no `location`, so an instance cannot tell from the event whether a Turn End is its business. Left alone, every instance handled every Turn End: duplicate Continuation Prompts, duplicate stop Notices, and a Loop that ran past its own completion because the reads and writes interleaved. We record the owning `ctx.location.directory` on the Loop state itself and make every read path ignore a Loop owned by another directory. The alternative, calling `ctx.session.get` on each event to compare the session's own location, costs a round trip per event for information the Loop already knows at start time; a process-scoped identifier was rejected because it would not survive the service restart that Resume exists to handle. The cost is a mutable ownership field on persisted state and a Loop that stops being handled if its owning location is unloaded, which `/ralph-loop` in the new location recovers from by claiming the key.
